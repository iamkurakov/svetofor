# Светофор — отчёт и ввод статистики

Один сайт «Светофор маркетинг»: результаты, план продвижения в магазинах, дорожная карта, финмодель и раздел **«Статистика»**. Хостинг — GitHub Pages.

В разделе «Статистика» сверху — метрики в виде инфографики (факт против плана по месяцам), ниже — ввод цифр по месяцам для SMM.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | весь сайт (один файл, без внешних скриптов) |
| `data/stats.json` | замеры по месяцам и посты: только числа и короткие заметки |
| `data/access.json` | появится сам после шага «Включить запись» (зашифрованный ключ доступа) |

## 1. Публикация (один раз, владелец)

1. Создайте репозиторий (например, `svetofor`). Загрузите `index.html` и папку `data`: Add file → Upload files.
2. Settings → Pages → Source: Deploy from a branch → `main` / `(root)` → Save.
3. Через 1–2 минуты сайт откроется по адресу `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`. Для этого репозитория: https://iamkurakov.github.io/svetofor/

> Бесплатный GitHub Pages работает только с публичными репозиториями: цифры и статистика будут видны всем, у кого есть ссылка. Нужна закрытость — платный тариф GitHub с приватными Pages.

## 2. Включить запись для SMM (один раз, владелец)

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
2. Repository access: **Only select repositories** → репозиторий сайта. Permissions → Repository permissions → **Contents: Read and write**. Срок — 1 год.
3. Откройте свой сайт на `github.io` → «Статистика» → внизу «Хранение и доступ» → «Включить запись для SMM».
4. Вставьте токен, придумайте **пароль для команды** (не короче 8 символов, лучше длинная фраза из 3–4 слов) → «Включить запись».
5. Передайте пароль SMM (мессенджером, не в публичных местах).

Сайт зашифрует токен паролем (PBKDF2 + AES-GCM) и сам сохранит файл `data/access.json`. Токен в открытом виде нигде не хранится.

## 3. Работа SMM (дважды в месяц)

1. Открыть сайт → «Статистика» → блок «Ввод по месяцам».
2. Первый раз на устройстве — ввести пароль («Открыть ввод»). Дальше сайт запомнит.
3. Выбрать месяц на ленте (Окт, Ноя, Дек…). Будущие месяцы закрыты («скоро») и откроются сами.
4. Вписать числа. Под полем видно «было … · план …» и отклонение от плана. Пустое поле = «не измеряли».
5. «Сохранить месяц». Метрики вверху страницы и весь отчёт пересчитаются.

Текущий месяц можно вносить и править несколько раз: данные записываются на сегодняшнюю дату. Для прошлых месяцев данные считаются на конец месяца. Пост: блок «Результаты поста».

Исправить: выбрать месяц, поменять число, «Сохранить месяц». Стереть: «Очистить месяц» (спросит подтверждение). Каждое сохранение — отдельная запись в истории репозитория, откат возможен средствами GitHub.

## 4. Владелец (раз в месяц)

Открывает сайт и смотрит первый экран раздела «Статистика»: плитки по каналам, графики по месяцам, таблицу «Выполнение плана». Зелёный — в норме (не ниже −3 % к плану), жёлтый — внимание (до −15 %), красный — отставание; для затрат наоборот.

## Что можно вводить

Только числа (проценты не больше 100, подписчики и просмотры — целые) и короткая заметка буквами и цифрами. Картинки и файлы не принимаются.

## Если что-то пошло не так

- **«Доступ устарел или отозван (401)»**: токен истёк или отозван. Введённые цифры не потеряны, они лежат в браузере и уйдут после обновления доступа. Владелец повторяет шаг 2 с новым токеном (пароль можно оставить прежним).
- **Нет связи с GitHub**: цифры сохраняются в этом браузере, в статусе виден счётчик «Не отправлено», отправятся при следующем сохранении или по кнопке «Обновить данные».
- **Запасной путь без GitHub**: «Хранение и доступ» → «Скопировать JSON» или «Скачать файл», затем заменить `data/stats.json` в репозитории вручную (Edit file). «Загрузить файл» читает такой JSON обратно.
- **Изменения не видны сразу**: у GitHub Pages задержка до минуты; «Обновить данные» перечитывает файл.
- **Сменить пароль**: владелец повторяет шаг 2 с новым паролем и сообщает его SMM; на старых устройствах SMM нажмёт «Выйти на этом устройстве».

## Безопасность — коротко

- Репозиторий публичный: `data/stats.json` и `data/access.json` видны всем. В первом лежат только числа, во втором — зашифрованный токен.
- Если пароль простой, его можно подобрать. Поэтому пароль — длинная фраза, а токен выпускается на один репозиторий с правом только Contents. В худшем случае посторонний может менять файлы этого репозитория: тогда отзовите токен в GitHub и повторите шаг 2.
- Не отправляйте токен в чаты и не публикуйте пароль.

## Ограничения

- Расчёт ведётся по одному региону — Алтайскому краю. Второй регион в план не включён.
- Два человека одновременно: перед записью сайт перечитывает файл и повторяет попытку при конфликте.
- Запись в GitHub работает на вашем адресе `github.io`. В окне предпросмотра Claude доступ к GitHub закрыт — там работает только локальный режим (данные остаются в браузере).
